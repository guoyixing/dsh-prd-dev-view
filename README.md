# PRD 研发视图 · DSH 插件

在 DeepSeek Harness (DSH) 中把 PRD 与代码对照整理为功能矩阵、功能卡片、冲突与改造清单，并在会话的「研发视图」页签中评审和跟踪。

## 功能

- 功能矩阵与阶段式功能卡片，点击高亮关联和连线。
- 业务全貌、共用规则、影响地图，以及完整冲突/改造清单。
- 每个会话绑定一份视图；已完成条目保留，不直接删除。
- 原生右侧栏创建视图，托管 Markdown PRD 及其本地图片。
- 真实的创建任务与模型上报生成进度；提示默认紧凑，关闭后不占空间。
- 对比 Git 基线，将代码证据命中的条目标记为待复核。
- 模型工具 `prd_view`、`prd_view_edit`，以及随包提供的 `prd-dev-view` skill。
- 导出可独立打开的只读 HTML。

## 环境要求

DSH 版本范围：`>=0.2.2-rc.1 <0.3.0-0`。当前功能开发与宿主 API 核验基于 `0.2.2-rc.3`；其他版本仍需实际验证。需要 Web 界面；代码同步需要本机 Git。

## 安装

在 DSH 插件管理器中安装 npm 包 `dsh-prd-dev-view`，再确认 bundle 与插件启用状态。不要用普通 `npm install` 替代 DSH 的插件安装流程。

源码开发时可在 DSH 插件管理器中选择本项目的本地目录安装。旧版本本地包名为 `@local/dsh-prd-dev-view`，新包名为 `dsh-prd-dev-view`；迁移时先移除旧的 bundle 安装记录，再安装新名称，避免重复注册工具或页签。移除安装记录不代表删除项目中的视图数据；迁移前请自行备份重要数据。

## 使用

1. 进入一个有工作目录的会话，点击输入框上方分支选项旁的「研发视图」，打开原生创建栏。
2. 选择 Markdown PRD、填写视图名称与保存位置。默认保存到项目内 `.dsh/prd-views/`。
3. 检查生成请求草稿后自行发送。创建文件不等于已生成业务内容。
4. 打开「研发视图」页签评审功能及关联清单。通过会话头部选择器切换绑定。
5. 代码变更后同步并复核相关条目，保留完成记录。

详细行为、进度语义和限制见 [功能说明](docs/DETAIL.md)。

## 数据与隐私

视图数据及托管 PRD 存放在用户选择的项目目录；会话绑定、源文档位置、创建任务和生成状态等个人信息保存在本机插件状态目录。示例模板完全虚构，不包含真实项目 PRD。

请在共享自己的视图前检查业务内容、代码证据与路径。本仓库忽略本地视图数据、缓存、环境配置和临时备份；npm 使用文件白名单，仅包含插件运行资源与说明。

## 开发与测试

建议使用 Node.js 22 或更高版本。克隆仓库后运行：

```sh
npm ci
npm test
npm pack --dry-run
```

测试依赖 React 18 和 jsdom，仅用于开发，不随插件安装。测试包含模型/服务、创建任务、生成状态、Host 路由、界面行为和脱敏模板导出回归。DOM 测试不等于真实浏览器布局或视觉验收。

## 已知限制

- 无会话的首页不显示创建入口，需先进入空会话。
- 窄屏创建入口提示扩宽窗口，不打开全屏遮罩。
- 关闭提示的偏好在当前 Client 生命周期内保留，刷新后可能重现。
- 同步基于基线提交与工作目录，不自动实施跨分支保护。
- Shell 直接写文件不能被模型文件修改守卫拦截。
- 导出的 HTML 为旧版只读模板，不是实时协作页面。
