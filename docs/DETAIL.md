# PRD 研发视图

把业务 PRD 与现有代码对照后整理成**一份数据文件**（`*.prdview.json`），在 DSH 里评审和跟踪。

## 在哪里用

- **会话顶部「研发视图」页签**：功能矩阵（单击点亮关联，双击开卡片）、完整功能卡片（阶段 × 处理步骤/调整/冲突/兼容，点击画连线）、冲突与改造总清单（筛选、分组，已完成折叠保留）、业务全貌、影响地图、共用规则。右侧详情可直接标记完成、答复问题、复核代码变化，或把条目引用到输入框。
- **会话头部右侧的「研发视图」选择器**：每个对话绑定一份研发视图。项目 `.dsh/prd-views/` 中有视图时默认绑定第一份，选「无」取消。只有绑定的对话能修改这份视图、收到改代码后的同步提醒；未绑定的对话看不到编辑工具。
- **项目内存放**：新建视图时填写 PRD 文档的路径（只支持 Markdown），视图保存在 `<保存位置>/<名称>/`，内含数据文件 `<名称>.prdview.json`、复制进来的 PRD 文档 `<PRD名>.md` 和它引用的本地图片 `<PRD名>.assets/`，随项目共享和版本管理。保存位置默认是项目根目录的 `.dsh/prd-views`，新建时可改，默认值在设置中修改。导出的 HTML 在同目录，是否提交由你决定。对话绑定、PRD 原文件位置等个人状态保存在本机，不进项目。
- **PRD 文档托管**：复制时只改写图片链接、不增删行，PRD 行号引用保持有效；网络图片保持原链接，找不到的图片会列出来但不阻止创建。总览页显示当前 PRD 文档，可「从原文件更新」或更换；模型不能直接修改 PRD 文档及其图片。
- **设置 › PRD 研发视图**：登记数据文件、导入旧版 HTML、编辑导出路径与代码仓库，开关自动导出、修改拦截和改代码提醒。
- **模型工具**：`prd_view`（查询、检查、同步、导入、导出）与 `prd_view_edit`（编辑操作）；随插件提供 `prd-dev-view` skill。

## 从初始页创建与查看进度

已有空会话的初始页，在输入框上方 workspace/preset 行右侧、分支选项旁提供紧凑「研发视图」入口。点击只打开原生右侧创建栏，不发送消息、不启动模型、不创建会话或工作树，也不更改模式、模型、分支或已有草稿。移除了页面顶部全宽横条和包裹原生聊天的 hero.frame 注册；入口只加载自身局部样式，不接管聊天或输入框布局。窄屏（小于 768px）会就地提示扩宽窗口，不打开全屏遮罩。

**无会话首页限制**：当前 DSH `0.2.2-rc.3` 的 `conversation.hero.options` 是 `list/session`，宿主在 `sessionId` 不存在时不渲染它。此时不会显示入口，请先通过原生项目选择器进入空会话，再点击研发视图。该位置是用户接受的「分支旁」位置，不是紧贴「标准模式」右侧：原生 preset 是已占用的 single slot，不应抢占。

**安装源核验**（本次未修改宿主）：`dsh-client-ui-conversation/src/client/apply.ts:353–357` 声明 frame/hoc、agentPreset/single/session-maybe、options/list/session；`skeleton/ConversationContent.tsx:132–133` 在 preset 后渲染 options，并限制有会话；`skeleton/ConversationRoot.module.css:620–627` 用 `margin-left:auto` 将 options 放在行右端。插件以 order 10 注册该 list；不使用 DOM 查询、宿主 CSS 重排或猜测的追加 API。待打开意图以 slot 的 sessionId 为目标，等待原生侧栏 mounted 匹配；同会话入口重挂载可恢复，切换会话会取消旧意图，不误开旧会话。

表单沿用 PRD 路径、视图名称、保存位置和最终目录预览。输入框已有草稿不会覆盖。jsdom 测试只覆盖注册、生命周期及行为回归，不是浏览器布局或视觉验收；没有认证浏览器时不声称完成视觉验收。

创建任务由 Host 管理，收起侧栏不取消。阶段依次为检查文档、复制文档及图片、保存视图、绑定会话、创建完成。图片显示实际已复制数量和字节，不模拟整体百分比；缺失图片单列且允许继续。刷新后重新读取本机任务记录；Host 重启时未结束的任务标为中断，需用户重试。视图已保存而绑定失败时，只重试绑定，不重复生成文件。创建过程中若用户改选其他绑定，不会在后台完成时强行改回，需要用户明确确认绑定新视图。失败原因保留在侧栏，不仅弹出短暂通知。

“创建完成”只代表文件和绑定就绪，不代表业务内容已经生成。空视图显示“内容待生成”，请求只在空输入框中自动预填；有草稿时由用户明确插入。发送请求后，模型通过 `prd_view action=generation` 上报实际阶段与已确定的功能计划。卡片计数只累计明确确认且通过基本完整性检查的卡片；完成还须通过数据检查。未上报不推测，页面展示最后上报时间，不能将其当作模型仍在运行的证据。

### 紧凑生成提示

研发视图顶部将草稿提醒与生成状态合为单行，默认只显示真实阶段、最后上报标记和已知计数。「查看详情」按需展开最后上报说明、时间、错误及适用的草稿操作；收起时不挂载长文本，展开区域限高并可独立滚动，避免长路径或错误挤占主要内容。「关闭提示」后整个提示区域不渲染任何 DOM，不保留按钮、占位或留白，也不提供原位重新打开入口；状态和历史不会被删除，后台仍继续读取生成状态。

关闭/展开偏好只保存在当前 Client 生命周期的会话 store，按会话和视图分别隔离。关闭后，卸载重挂、切换视图再返回，以及在研发视图页签和原生右侧栏之间切换，均保持隐藏；需要主动重新查看时可刷新页面。阶段变化会重新提醒，新生成轮次（startedAt）、相关创建任务或错误发生变化也会再次显示紧凑提醒；同阶段计数、说明或更新时间变化不会反复打断。失败/中断保持清晰阶段标签，错误全文可展开查看。查看详情和关闭提示不发消息、不更改 PRD 数据或历史日志。

读取到生成已开始、完成、失败或中断的真实上报后，不再显示旧创建任务的「内容待生成」草稿提示，也不再次自动预填其请求。尚无上报时仅说明「尚无生成上报；请检查对话，按需发送生成请求」，不推断用户是否已经发送。等待状态读取期间或状态读取失败时不对已绑定视图自动预填；有草稿仍保留，只有显式插入才追加且不发送。切换视图后不沿用上一视图的状态或创建请求，迟到的轮询响应会丢弃；卸载会清理轮询。

创建任务、原文件路径和生成阶段记录保存在本机插件状态目录，随项目共享的视图文件不携带这些本机路径记录。

## 保证

- 条目只能关闭或标记被取代，不能删除；保存前比对上一版编号。
- 关系只存一处，功能侧列表、计数和卡片引用全部推导。
- 模型用 write / edit 直接改数据文件或生成的 HTML 会被拒绝。
- 同步按证据比对代码基线，把受影响条目标为待复核。

## 限制

- PowerShell 等命令直接写文件无法拦截，也无法触发改代码提醒。
- 导出的 HTML 使用旧版只读模板。
